## 📌 このトピックの本質
サイクリック・コンプレックス性（Cyclomatic Complexity）とは、コードが**分岐構造（if/else、switch、for、whileなど）**によってどれだけ複雑になっているかを数値化した指標です。この値が高いと、バグの発生リスクや保守コストが増大し、テストやデバッグが難しくなります。C#では、この指標を意識的に管理することで、より**読みやすく、維持しやすいコード**を書くことが可能です。

## 🎯 5秒で分かるポイント
- **Point 1**: **値が5以上**のメソッドは、リファクタリングの候補。
- **Point 2**: **分岐の数**が増えると、サイクリック・コンプレックス性も増加。
- **Point 3**: **NDepend**や**SonarQube**などのツールで自動計測可能。

## 📊 詳細解説
**サイクリック・コンプレックス性の計算方法**
サイクリック・コンプレックス性は、**分岐構造の数**に基づいて計算されます。例えば、以下のコードでは`if`文が2つあるため、値は**3**になります（分岐数+1）。

```
if (条件1) { ... }
else if (条件2) { ... }
```

> 💡 ポイント: **関数の入れ子**や**多重条件**も、値を大きくします。1つの条件文に複数の条件を書かず、分割することが重要です。

**リファクタリングの具体例**
以下のコードはサイクリック・コンプレックス性が高い例です。

```
public int CalculateDiscount(int age, bool isMember, string tier) {
    if (age < 18) return 10;
    else if (age >= 18 && age < 65 && isMember) return 15;
    else if (age >= 65) return 20;
    else if (tier == "Gold") return 30;
    return 0;
}
```

このコードは**分岐が多く、条件が複雑**です。リファクタリングすると以下のようになり、サイクリック・コンプレックス性が大幅に低減します。

```
public int CalculateDiscount(int age, bool isMember, string tier) {
    int baseDiscount = 0;
    if (age < 18) baseDiscount = 10;
    else if (age >= 65) baseDiscount = 20;
    if (isMember) baseDiscount = Math.Max(baseDiscount, 15);
    if (tier == "Gold") baseDiscount = Math.Max(baseDiscount, 30);
    return baseDiscount;
}
```

**ツールによる自動計測**
NDependやSonarQubeなどの静的解析ツールを使うと、プロジェクト全体のサイクリック・コンプレックス性を可視化できます。例えば、NDependは**ダッシュボード**でメソッドごとの値を表示し、リファクタリングの優先順位を示します。

> 💡 ポイント: **CI/CDパイプライン**に組み込むことで、コミットごとに自動チェックが可能。

## 🚀 実世界への影響
- **バグの増加**: サイクリック・コンプレックス性が高いコードは、テストが不十分になりやすく、バグが発生しやすくなります。
- **保守コストの上昇**: 後から変更する際に、理解やテストのコストが増大。チームの生産性が低下します。
- **スケーラビリティの低下**: 大規模なプロジェクトでは、複雑なコードがボトルネックになり、新機能の追加が遅延します。

## ✨ 結論
サイクリック・コンプレックス性は、**コードの品質を測る重要な指標**です。C#開発では、この値を意識的に管理し、ツールを活用してリファクタリングを実施することで、より**安定した、保守しやすいコード**を作り出せます。小さな改善が、長期的なプロジェクトの成功を左右します。
