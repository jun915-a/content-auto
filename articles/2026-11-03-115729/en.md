This setup turns your PC into a **text-based UI (TUI) scanner**, revealing hidden wireless activity in plain sight. Key pins include **GDO0** (for data ready), **SCK**, **MOSI**, and **MISO** (SPI communication). A **3.3V regulator** is critical—CC1101 operates at 3.3V, while the FT232H runs at 5V. Use a **logic level converter** if needed. The FT232H’s USB port provides power, so ensure proper grounding to avoid noise.\n\n> 💡 Insight: **SPI timing is critical**—erratic wiring can cause packet corruption. Double-check connections before powering up.\n\n**Software Stack & Libraries**\nThe project relies on Python for its simplicity and libraries like `pyftdi` to communicate with the FT232H. The `cc1101` library abstracts the SPI protocol, letting you configure the transceiver (e.g., frequency, modulation) via Python. For the TUI, **`curses`** or **`rich`** libraries render decoded packets in a terminal-friendly format. Decoding involves:\n1. **Syncing** to the preamble (start of packet).\n2. **Extracting** the payload (e.g., a 4-byte remote control ID).\n3. **Filtering** noise using signal strength indicators (RSSI).\nAdvanced users can extend this to **learn protocols** like **433MHz RF4CE** or **Zigbee** by tweaking the library’s packet parsing.\n\n> 💡 Insight: **Not all devices use standard protocols**—some use proprietary encoding.
