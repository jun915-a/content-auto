## 🔑 The Core of This Topic
This project achieved the seemingly impossible: running the original Doom game entirely within a SQL database. Instead of traditional graphics rendering, game elements like sprites, maps, and player data are stored and manipulated as SQL tables and queries. It's a demonstration of how database technology can be stretched to unconventional, creative applications.

## ⚡ 5-Second Key Points
- **SQL Rendering**: Game visuals are generated using SQL queries.
- **Data-Driven Gameplay**: All game states and assets reside in database tables.
- **Unconventional Port**: A unique fusion of gaming and database technology.

## 📈 Detailed Breakdown
**Rendering Engine**
The game's visuals are constructed by querying database tables that represent pixels or small graphical chunks. Complex SQL statements define how these elements are drawn, colored, and positioned, effectively simulating a graphics pipeline.

**Game Logic and State**
Player position, enemy AI, weapon status, and map layouts are all managed through SQL table entries and transactions. Every action triggers database updates, maintaining the game's persistent state.

> 💡 Insight: This showcases how structured data can represent and drive complex interactive systems, blurring the lines between application logic and data management.

**Asset Management**
Even game assets like textures and sounds are translated into SQL data. This involves encoding graphical data into formats that SQL can store and process, a significant challenge in itself.
