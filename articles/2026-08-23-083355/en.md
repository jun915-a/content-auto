# Scrap (2006): Moxie's Vision for a Decentralized Web

Explore Scrap (2006), a foundational concept by Moxie Marlinspike, envisioning a decentralized internet. Learn about its core principles and lasting influence on web architecture.

## 🔑 The Core of This Topic
Scrap (2006) represents an early, visionary concept by Moxie Marlinspike for a decentralized web architecture. It proposed a system where data and services are distributed across a peer-to-peer network, moving away from centralized servers and fostering greater user control and resilience.

## ⚡ 5-Second Key Points
- **Decentralization**: Shifting power from central authorities to individual users.
- **Resilience**: Creating a web less prone to single points of failure.
- **User Control**: Empowering individuals with ownership over their data and online presence.

## 📈 Detailed Breakdown
**Peer-to-Peer Data Storage**
Scrap envisioned data being stored and retrieved directly from other users' machines, eliminating the need for massive, centralized data centers. This distribution enhances privacy and reduces reliance on third-party providers.

**Distributed Services**
Instead of relying on single company servers for applications, Scrap suggested services could run across a network of peers. This fosters a more robust and censorship-resistant internet ecosystem, where applications are always available.

> 💡 Insight: The core idea was to build an internet that is inherently more robust and less controlled by any single entity, prioritizing user autonomy.

## 🎯 Real-World Impact
- Laid groundwork for future decentralized technologies and protocols.
- Influenced the development of peer-to-peer file sharing and secure communication systems.
- Continues to inspire modern decentralized web (Web3) initiatives.

## ✨ Conclusion
Scrap (2006) remains a significant, albeit less known, contribution to the ongoing evolution of the internet, championing a future where the web is more open, resilient, and user-centric.
